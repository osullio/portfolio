Overview

I spent eight months on a software team working on Cadence Virtuoso, the industry-standard platform for custom IC design. My work split into two areas: fixing bugs in the product and an open-ended UI project.

Product bug fixes

I fixed issues reported by customers and product engineers, working in a large production C++ and SKILL codebase. Each one followed the same process:

  • Reproduce the issue and track down the root cause
  • Make a fix that doesn't cause regressions elsewhere
  • Write a test case to stop the bug coming back
  • Get the change through peer code review

UI project: Qt inside Virtuoso

I looked into whether Qt, a mainstream C++ UI framework, could be used to build user interfaces inside Virtuoso instead of its built-in SKILL-based forms. I started with small prototypes and worked up to a Qt widget running inside the product. That proved the approach works, and I reported back on where it is and isn't worth using. I presented the work, including a live demo, to the team and management.

What I took away

  • Working confidently in a large, mature C++ codebase and its build system
  • A disciplined bug-fixing process, and how much better code gets with senior review
  • New languages and frameworks: SKILL (Lisp-based) and Qt
  • Taking ownership of open-ended work and presenting it to stakeholders
