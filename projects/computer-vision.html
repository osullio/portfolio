Abandoned & Removed Object Detection

Computer Vision module · Year 4, TCD · Individual assignment

  • C++
  • OpenCV 4.12
  • Background subtraction
  • Object tracking
  • Evaluation
View code on GitHub Read the full report (PDF)

Overview

Surveillance systems need to flag two kinds of change: a bag that's been left behind, and something that's been taken. I wrote an OpenCV/C++ program that finds both in video, labels each detection as abandoned or removed, and scores itself against hand-labelled ground truth.

How it works

  1. Background subtraction. A Gaussian Mixture Model (BackgroundSubtractorMOG2) separates foreground from background.
  2. Motion mask. Differencing each frame against one from five frames earlier separates moving foreground from static foreground.
  3. Persistence. Pixels that stay foreground without moving build up a count. A region that stays still for about 6 seconds becomes a candidate.
  4. Filtering & tracking. Candidates are filtered by area (150–3000 px) and aspect ratio, tracked across frames, merged when they overlap, and confirmed after 15 consistent frames.
  5. Classification. Edges in the current frame are compared with a baseline of the empty scene. New edges mean an object was abandoned. Edges that have gone missing mean one was removed.

Evaluation

Each detection is matched to ground truth when IoU ≥ 0.5 and it falls within ±120 frames. The program reports precision, recall and F1 for each video and overall, plus classification accuracy.

Results: overall F1 of 0.364. Recall was the strongest of the three metrics, which suits the application: for a bomb scare or a theft, a false alarm is far better than a miss.

Where it falls short

  • Video 10. Tracking many candidates, each with its own votes and a historic baseline, was too heavy for the most disruptive video, and the program crashed on it.
  • Second events. The slow GMM learning rate keeps a left object from fading too soon, but it also means the scene takes a long time to settle, so a bag that is abandoned and later removed only triggers once.
  • People standing still. Someone who stays still for long enough looks exactly like a static object. Tuning reduced this but didn't remove it.
  • Small objects. Ignoring regions under 150 px cut a lot of noise but missed the small bag in Video 5. I tested lower limits and decided the trade-off wasn't worth it.

What I learned

  • Tuning thresholds is always a trade-off: a shorter persistence window catches more objects but brings in false alarms from people standing still.
  • Requiring 15 consistent frames before classifying cut false positives from the thousands to single digits, at the cost of extra computation.
  • Ground truth has opinions too. My detector flagged reflections in a monitor that changed when the scene changed. They're real changes, but the labels don't count them.

What I'd do next

  • Reduce the computational load so Video 10 runs and the full dataset is covered.
  • Experiment with GMM learning rates so repeat events in the same spot are detected.
  • Try other classification techniques, and combinations of them, to fix misclassifications.
  • Make the pipeline cross-platform (it currently builds with MSVC on Windows only).
